# DOCX audit rules split

Источник: `Google AI Studio/00_AUDIT_RULES_MASTER.md` и
`Google AI Studio/00_AUDIT_RULES_MASTER_RECOMMENDED.md`.

Цель: разделить общий audit-набор на правила, которые можно безопасно выполнять
в этом проекте детерминированно, и остаток для AI-вычитки.

## Файлы правил

Правила `system_core/docx_audit_processor.py` лежат данными в `config/rules`,
по файлу на раздел. Движок читает их при каждом запуске; в окне **Аудит правил
DOCX** у каждого файла своя галочка. Карта файлов и AI-остатка -
`config/rules/rules.yaml`.

| Файл | Раздел | По умолчанию |
|---|---|---|
| `units.yaml` | Единицы измерения, проценты и градусы | вкл |
| `house.yaml` | Правила проекта: `№`, даты, подписи таблиц и рисунков | вкл |
| `abbreviations.yaml` | Сокращения | вкл, только отчёт |
| `acronyms.yaml` | Аббревиатуры | вкл, `РФ` и кандидаты только в отчёт |
| `addresses.yaml` | Исправления адресов | выкл, только отчёт |

Порядок применения от галочек не зависит: единицы, правила проекта, сокращения,
аббревиатуры, адреса.

### Как устроено правило

```yaml
- code: AUDIT-NUMBER-SIGN      # код в отчёте и в якорях
  status: implemented          # implemented или candidate
  action: fix                  # fix - исправляет, suggest - только в отчёт
  severity: minor
  title_ru: "Пробел после знака номера"
  match: '№{SP}*(?P<num>\d+)'  # регулярное выражение Python
  replace: '№ {num}'           # шаблон замены
  fix:                         # обязано получиться именно так
    "№1": "№ 1"
  keep:                        # обязано остаться как есть и не попасть в отчёт
    - "№ 1"
```

Вставки в `match`:

- `{NUM}` - число с группой `num`: `12`, `-5`, `1 000`, `0,5`;
- `{END}` - граница после единицы: конец текста, пробел или знак препинания;
- `{SP}` - обычный или неразрывный пробел;
- `{NBSP}` - неразрывный пробел;
- `{list:имя}` - альтернатива из раздела `lists` того же файла.

Вставки в `replace`:

- `{группа}` - текст именованной группы как есть;
- `{группа|canon}` - написание из словаря `canon` правила: `квт` -> `кВт`;
- `{группа?текст}` - текст, если группа нашлась;
- `{NBSP}` - неразрывный пробел.

Ещё поля правила: `sources` - на чём основано решение: пункт стандарта, приказ,
ответ Грамоты или норма проекта; тест не пропустит правило без источника.
`ignore_case: true` - без учёта регистра; `norms: [rules]` или
`norms: [gost]` - правило только для одной нормы; `cases` - несколько пар
`match` и `replace` под одним кодом, применяются по очереди. В YAML регулярное
выражение пишется в одинарных кавычках, а неразрывный пробел в примерах - в
двойных, как `"50\u00A0%"`.

Неразрывные пробелы авторы ставят сознательно. Обычный пробел шаблона там, где
в тексте стоял неразрывный, остаётся неразрывным; новый неразрывный пробел пишет
только `{NBSP}`. Снять неразрывный пробел могут лишь проценты и градусы по норме
`ПРАВИЛА`.

### Примеры - это тесты

При каждом запуске движок прогоняет примеры `fix` и `keep`. Правило, у которого
пример не сошёлся, и правило `fix` совсем без примеров документ не исправляют:
они работают только в отчёт, а замечание выходит в начало отчёта. Ошибка в одном
правиле или файле не выключает остальные.

Проверить все файлы в обеих нормах:

```
runtime\python.exe system_core\audit_rule_files.py
```

Каждое ложное срабатывание на реальной записке становится новым примером `keep`.

## Норма процентов и градусов

| Норма | Проценты | Температура | Угол |
|---|---|---|---|
| `ПРАВИЛА`, по умолчанию | `50%` | `5°C`, латинская C | `20°` |
| `ГОСТ` | `50 %` | `20 °C`, буква шкалы как в тексте | `20°` |

По норме `ГОСТ` между числом и знаком ставится неразрывный пробел. Переключатель
есть в окне **Аудит правил DOCX** и в **Форматировании документов** рядом с
галочкой «Единицы, №, %, градусы, даты».

## Правила проекта

| Код | Файл | Режим | Правило | Примеры |
|---|---|---|---|---|
| `AUDIT-UNIT-SQM` | `units.yaml` | `FIX` | Единицы площади приводятся к `кв. м` | `10кв.м`, `10 кв м`, `10 м2`, `10 м²`, `10 квадратных метров` -> `10 кв. м` |
| `AUDIT-UNIT-CUBIC` | `units.yaml` | `FIX` | Единицы объёма приводятся к `куб. м` | `15куб.м`, `15 м3`, `15 м³`, `15 кубических метров` -> `15 куб. м` |
| `AUDIT-UNIT-SPACE` | `units.yaml` | `FIX` | Пробел между числом и безопасным списком единиц | `10м` -> `10 м`, `20га` -> `20 га`, `3Гкал/ч` -> `3 Гкал/ч` |
| `AUDIT-PERCENT` | `units.yaml` | `FIX` | Процент по норме | `ПРАВИЛА`: `50 %` -> `50%`; `ГОСТ`: `50%` -> `50 %` |
| `AUDIT-DEGREE` | `units.yaml` | `FIX` | Градусы по норме | `ПРАВИЛА`: `5 °С` -> `5°C`; `ГОСТ`: `5°C` -> `5 °C`, `угол 20 °` -> `угол 20°` |
| `AUDIT-NUMBER-SIGN` | `house.yaml` | `FIX` | Пробел после знака номера | `№1` -> `№ 1` |
| `AUDIT-DATE-YEAR-SUFFIX` | `house.yaml` | `FIX` | Полная дата без `г.`, когда фраза продолжается | `20.12.2012 г. № 5` -> `20.12.2012 № 5` |
| `AUDIT-CAPTION-TABLE-TYPO` | `house.yaml` | `FIX` | Безопасные опечатки в подписи таблицы | `Таблрица. 3`, `Таблица. 3` -> `Таблица 3` |
| `AUDIT-RF-SCAN` | `acronyms.yaml` | `SUGGEST` | Сокращение `РФ` только фиксируется в отчёте | рекомендация: заменить полным названием с проверкой падежа |

Точка, которая может закрывать предложение, не снимается: `кв.м.` и `г.` после
даты теряют точку, только если фраза продолжается. Перед заглавной буквой и в
конце текста дата с `г.` уходит в отчёт правилом-кандидатом
`AUDIT-DATE-YEAR-SUFFIX-END`.

Ограничение текущей версии: processor меняет только отдельные текстовые узлы
DOCX `w:t`. Это сохраняет форматирование, но не ловит случаи, где выражение
разрезано Word на несколько run-ов.

## Кандидаты

Кандидаты работают только в отчёт, пока не проверены на корпусе записок. Правило
переводится в исправление сменой `action: suggest` на `action: fix`, когда на
корпусе у него нет ложных срабатываний.

| Код | Файл | Правило |
|---|---|---|
| `AUDIT-UNIT-SLASH` | `units.yaml` | Единица через косую черту без пробелов: `руб. / сут` -> `руб./сут` |
| `AUDIT-DATE-YEAR-SUFFIX-END` | `house.yaml` | Дата с `г.` перед заглавной буквой или в конце текста |
| `AUDIT-CAPTION-FIGURE-TYPO` | `house.yaml` | Опечатки в подписи рисунка: `Рисунок. 1`, `Риснунок 1` -> `Рисунок 1` |
| `AUDIT-INITIALS-JOINED` | `house.yaml` | Инициалы слитно по корпоративной норме: `И. И. Иванов` -> `И.И. Иванов`; в норме `ГОСТ` правила нет |
| `AUDIT-ABBR-REGISTRY` | `abbreviations.yaml` | Реестр технических сокращений с источниками: `кг.у.т./Гкал` -> `кг у.т./Гкал`, `т.у.т/год` -> `т у.т./год` (приказ Минэнерго № 323), `10 м.п.` -> `10 пог. м` (ОКЕИ 018), `у.е.` -> `у. е.` |
| `AUDIT-ABBR-COMPOUND` | `abbreviations.yaml` | `т.е.` -> `т. е.`, `и т.д.` -> `и т. д.` |
| `AUDIT-ABBR-MILLION` | `abbreviations.yaml` | `5 млн. руб.` -> `5 млн руб.` |
| `AUDIT-ABBR-THOUSAND` | `abbreviations.yaml` | `5 тыс руб.` -> `5 тыс. руб.` |
| `AUDIT-ABBR-RUB` | `abbreviations.yaml` | `100 руб` -> `100 руб.` |
| `AUDIT-ABBR-YEAR` | `abbreviations.yaml` | `2020г.` -> `2020 г.` |
| `AUDIT-ABBR-REFERENCE` | `abbreviations.yaml` | `п.3.1` -> `п. 3.1`, `ч.1 ст.5` -> `ч. 1 ст. 5` |
| `AUDIT-ACRONYM-CASE` | `acronyms.yaml` | `Гост` -> `ГОСТ`, `СНИП` -> `СНиП`, `Санпин` -> `СанПиН`, `190-фз` -> `190-ФЗ` |
| `AUDIT-ADDR-WRITING` | `addresses.yaml` | Адрес целиком по адресному движку: `п.Московский, ул.Новая, 1б` -> `п. Московский, ул. Новая, д. 1б` |
| `AUDIT-ADDR-TYPE-SPACE` | `addresses.yaml` | `г.Тюмень, ул.Ленина, д.5` -> `г. Тюмень, ул. Ленина, д. 5` |
| `AUDIT-ADDR-TYPE-DOT` | `addresses.yaml` | `ул Ленина, д 5` -> `ул. Ленина, д. 5` |
| `AUDIT-ADDR-DOUBLE-DOT` | `addresses.yaml` | `ул.. Свиридова` -> `ул. Свиридова` |

Ещё не сделано: дефис или минус с пробелами между словами, если это явно тире.

Гигиена текста с галочкой «Пробел после точки» не разбивает марки и коды латиницей
(`P61M-PR.S.RU.A.8.32.E.A.`) и сокращения реестра (`т у.т.`, `кг у.т.`, `м.п.`, `у.е.`):
как их писать, решает реестр, а не гигиена.

## Исправления адресов

`addresses.yaml` исправляет написание адреса: сокращения и пробелы.

Главное правило - `AUDIT-ADDR-WRITING`. Оно находит адрес целиком - населённый
пункт, улицу, дом - и пишет его так, как пишет адресный движок Audion Address
Processor: `п. Московский, ул. Новая, д. 1б`, `ст-ца Каневская`, `х. Лебяжий`,
`пр-кт Мира, д. 5, к. 1`. Типы населённых пунктов, улиц и частей дома - сотни
наименований - правило берёт из словарей движка вставками `{address:settlement}`
и `{address:street}`, а запись - фильтром `{группа|address}`. ОКТМО, индексы и
округа не участвуют.

Движку разрешено менять только написание: сокращения типов, точки, запятые,
пробелы. Названия, номера, литеры дома, дробь в номере и порядок частей обязаны
остаться как в тексте; если движок изменил бы что-то из этого, адрес не
трогается.

Обозначения в адресе строчные. Тип с заглавной буквы - это начало предложения,
имя или инициал («Г.Петров», «Д. Иванов», «Ул. Ленина» в начале фразы), и в адрес
он не попадает. Тип без точки берётся, только если он из двух букв и больше:
«с Ивановым» не адрес. Сокращению без точки движок точку ставит: `ул Ленина` ->
`ул. Ленина`, так же `пер`, `наб`, `пл`, `туп`, `ш`, `проул`, `пос`; `пр` без
точки остаётся как есть - это может быть и проспект, и проезд.

Движок лежит в `system_core/address_engine`: `audion_address_core.py`,
`address_slots.py` и `models.py` - точные копии из Audion Address Processor.
Правятся они там и копируются сюда без изменений; тест сверяет копии, когда оба
проекта лежат рядом. Без движка правило пропускается с замечанием, остальные
работают.

Узкие правила `AUDIT-ADDR-TYPE-SPACE`, `AUDIT-ADDR-TYPE-DOT` и
`AUDIT-ADDR-DOUBLE-DOT` ловят сокращение и вне полного адреса: `ул.Ленина` без
дома, `д.5`, `ул..`.

Правильность самого адреса - название улицы, существование дома, падеж
топонима - правилами не проверить: для этого нужен справочник или LLM.

### Где решения расходятся с источником

- Площадь и объём: проект пишет `кв. м` и `куб. м`, ГОСТ 8.417-2024 - `м²` и `м³`.
- Проценты и градусы по норме `ПРАВИЛА` пишутся вплотную к числу, ГОСТ 8.417-2024 требует пробел.
- ГОСТ 8.417-2024, п. 8.13: в диапазоне значений знаки `%`, `°C` и `°` ставят за каждым
  числом - `10 %–15 %`; такого правила пока нет.
- Адресный движок пишет `пгт` и `р. п.`, а по приказу № 171н - `пгт.` и `рп.`. Сокращение
  `пос.` движок оставляет как есть, а по приказу `пос.` - это поселение, посёлок - `п.`.

## Workflow с якорями

По умолчанию операция **Аудит правил DOCX** дополнительно создаёт копии
`*__annotated.docx` в `output/audit_annotated`. В этих копиях исходный текст
остаётся неисправленным, а рядом с найденными местами ставятся служебные якоря
вида `⟦A0001 AUDIT-UNIT-SQM⟧`.

Такой файл удобно отдавать на просмотр: пользователь видит, где именно сработали
детерминированные правила, вносит или одобряет правки, а затем запускает
техническую операцию **Снять якоря DOCX**. Она удаляет все служебные якоря из
`*__annotated.docx` и пишет чистые копии в `output/audit_unanchored`.

## Остаток для AI-вычитки

Эти правила остаются в AI-процессе, потому что требуют смысла, падежа,
юридического контекста, проверки источников или аккуратной интерпретации
таблиц.

| Блок | Почему не автоматом |
|---|---|
| Антигаллюцинация и запрет замечаний без опоры в тексте | Это инструкция поведения аудитора, а не правка документа. |
| Замена `РФ` полным названием | Нужен падеж, плюс защита цитат, реквизитов и официальных названий. |
| Защита формулировок вроде `городской округ город Тюмень` | Это guardrail против ложной правки. |
| Склонение топонимов | Требует грамматики и контекста. |
| Правильность адресов | Название улицы, номер дома и падеж проверяются по справочнику или смыслу. |
| Реалистичность чисел | Нужны предметные знания о населении, площади и соразмерности величин. |
| Хронология НПА и актуальность редакций | Требует знания дат актов и текущей редакции. |
| Согласование и однородность списков | Требует синтаксического и смыслового анализа. |
| Иерархическая нумерация пунктов, таблиц и рисунков | Ошибка зависит от уровня, родителя и границ разделов. |
| Смысловая структура таблиц | Сложные шапки и объединённые ячейки допустимы; нужна интерпретация данных. |
| Кавычки в названиях, цитатах и источниках | Автоунификация опасна для точных названий и выдержек. |
| Форматы НПА, ГОСТ, СП, СанПиН | Требуют понимания вида акта и официального названия. |
| Библиография и сноски | Нужны тип источника, повторность ссылки и контекст. |
